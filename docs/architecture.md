# 架构说明

## 目标边界

本框架只实现校内软件模拟态，不接入真实 Hi3861/Hi3516、传感器、网关、GPIO/I2C/SPI/UART 或真实 MQTT Broker。文档中的硬件与基地阶段内容被作为后续兼容方向，不作为当前代码目标。

## 模块划分

```text
模拟设备层
  产生光照、心跳、在线状态和控制回执
        |
        v
后端服务层
  REST API / SSE / 自动控制 / 告警检测 / 数据持久化
        |
        v
前端可视化层
  监测大盘 / 设备管理 / 告警日志 / 阈值配置 / 维护问答
```

## 核心数据流

1. 模拟器按周期为在线设备产生光照数据和心跳。
2. 后端接收遥测数据，写入历史记录，更新设备实时状态。
3. 自动控制逻辑依据阈值判断开灯或关灯，并生成控制记录。
4. 心跳检测任务发现设备超时后标记离线，并生成离线告警。
5. 前端通过 SSE 接收最新摘要，自动刷新实时卡片、趋势图、设备表和告警表。

## 可替换接口

- `receiveTelemetry`：后续替换为 MQTT 订阅入口。
- `sendControlCommand`：后续替换为 MQTT 指令发布。
- `saveState` / `loadState`：后续替换为数据库仓储。
- `answerMaintenanceQuestion`：后续替换为真实 RAG 或智能体工作流。
