# 智慧路灯前端优化 Prompts

这组 Prompt 面向本仓库的 `frontend/` 工程，可直接粘贴给 Codex、ChatGPT 或其他具备代码读写能力的编程助手。优先使用“主 Prompt”；范围较小时，再使用后面的专项 Prompt。

## 使用方式

1. 将 Prompt 中的 `[本次任务]`、`[目标页面]`、`[参考图或设计要求]` 替换为实际内容。
2. 如果没有参考图，明确写“无参考图，遵循现有设计系统”。
3. 一次只设一个清晰目标。先完成并验收，再发下一条专项 Prompt。
4. 若只想获取建议、不希望修改代码，将“直接实施”改为“只审计并输出建议，不修改文件”。

## 1. 主 Prompt：完整前端优化（推荐）

```text
你是一名资深前端工程师、产品设计师和可访问性审查员。请直接优化当前仓库中的智慧路灯前端，完成可运行、可验证的代码，而不是只给建议或伪代码。

目标
- 本次任务：[填写具体目标，例如“统一全站视觉层级并重点优化运行概览、实时监控和移动端导航”]
- 用户：需要长时间监控、快速扫描异常并频繁操作设备的运维人员。
- 成功标准：界面更清晰、紧凑、稳定、易操作；现有功能与接口行为不回退；桌面和移动端均无明显布局问题；构建和相关 QA 通过。

项目上下文
- 前端目录：frontend/
- 技术栈：Vue 3、TypeScript、Vite、Vue Router、Element Plus、ECharts、高德地图。
- 主要页面：Login、Dashboard、Monitor、Control、Alarms、DeviceManage、Chat、Users。
- 全局样式与设计令牌：frontend/src/styles/index.css。
- 主布局：frontend/src/layout/MainLayout.vue。
- API 封装：frontend/src/api/。保留现有接口路径、请求格式和响应类型。
- 现有视觉方向：夜间城市指挥中心；深色表面、克制的“路灯金”强调色、清晰的在线/离线/告警语义色、数据使用等宽数字。
- 已有验证工具：frontend/scripts/qa.mjs、frontend/scripts/screenshot.mjs。

工作原则
- 先检查相关文件、复用现有设计令牌、组件、图标库和交互模式，再修改代码。
- 只实现本次任务所需内容，不增加无关功能、页面、营销文案或装饰。
- 保留现有业务逻辑、路由、权限、接口契约和实时数据能力。除非修复明确问题，不改变后端依赖。
- 优先做根因级改进；不要用大量局部覆盖、魔法数字或重复 CSS 掩盖结构问题。
- 可以自主读取文件、编辑范围内代码、运行非破坏性检查。只有在需求歧义会显著改变结果时才提问；其余情况采用最简单、最符合现有系统的解释继续完成。
- 不要为了通过检查而隐藏内容、删除断言或绕过错误。若现有 QA 断言已与明确的设计契约不一致，可更新断言，但必须说明原因。

视觉与体验要求
- 将产品设计为高频使用的运维控制台：安静、实用、信息密度适中，支持快速扫描、比较和连续操作。
- 不制作落地页或大面积 Hero；首屏直接呈现真实的监控或操作界面。
- 建立清晰层级：页面标题、关键指标、主要工作区、次要信息和操作优先级一眼可辨。
- 避免卡片套卡片、把每个区块都做成悬浮卡片、无意义渐变球/光斑、过度圆角、过多阴影和纯装饰动画。
- 复用 `@element-plus/icons-vue` 中的图标，不手绘已有图标；图标按钮提供可访问名称，含义不明显时提供 tooltip。
- 使用熟悉的控件表达行为：开关对应二元状态，分段控件或标签页对应视图切换，下拉菜单对应选项集，按钮只用于明确命令。
- 状态不能只依赖颜色；在线、离线、告警、成功、警告应同时有文字、图标或形状提示。
- 所有可交互元素具有 hover、focus-visible、active、disabled 状态；危险操作需要清晰区分并保留确认流程。
- 页面文案简洁、准确、面向任务，不在界面中堆放“这是某功能”“点击这里使用”等说明性废话。
- 表格、指标、图表和地图优先保证可读性与数据真实性；不要用装饰牺牲坐标、图例、单位、状态或操作入口。

响应式与稳定性
- 至少检查 1440×900、1024×768、768×1024、390×844。
- 不允许页面级横向滚动、文本溢出、控件重叠、内容被固定栏遮挡或关键操作落到不可达区域。
- 桌面端保留高效侧栏与工作区；窄屏导航必须可识别、可操作，不能只剩没有提示的图标。
- 为地图、图表、表格、工具栏、按钮和动态指标设置稳定的尺寸约束，避免数据加载、hover 或标签变化导致布局跳动。
- 长文本、异常大数值、空列表、慢请求和接口失败时布局仍保持稳定。

完整状态
- 对所有受影响的异步区域检查并完善：首次加载、局部刷新、空数据、错误、重试、离线、无权限、禁用和成功反馈。
- 加载状态不得伪造数据；错误信息应给出可执行的恢复方式；刷新时尽量保留已有内容，避免整页闪烁。
- 轮询、SSE、ECharts、地图、事件监听器和定时器在组件卸载时正确释放；避免重复请求、竞态和重复实例。

可访问性
- 使用语义化 HTML；只触发动作的元素使用 button，不用无键盘行为的 div/span 冒充按钮。
- 表单有可关联的 label，错误信息可被辅助技术识别；键盘可完成核心流程，焦点顺序符合视觉顺序。
- 正文和关键数据满足 WCAG AA 对比度目标；焦点环清晰；不要只通过颜色传达状态。
- 尊重 `prefers-reduced-motion`，非必要动画在减少动态效果时关闭。

性能与代码质量
- 不添加不必要依赖；优先使用当前 Vue、Element Plus、ECharts 和工具函数。
- 避免重复计算、无界深度监听、重复渲染图表/地图、未清理监听器和并发轮询。
- 对非首屏重型页面或模块，在确有收益且不破坏体验时使用路由或组件级懒加载。
- 保持 TypeScript 类型明确，避免新增 `any`；抽取真正复用的逻辑，但不要为一次性样式过度抽象。
- 合并重复样式，优先使用全局设计令牌；不要新增与现有令牌冲突的任意颜色、圆角和阴影。

执行顺序
1. 阅读与任务相关的页面、布局、全局样式、路由、API 类型和验证脚本。
2. 用简短清单指出最重要的问题、证据和修改范围；不要停在审计阶段。
3. 实施影响最大且风险可控的优化，保持改动聚焦。
4. 运行 `npm run build`。
5. 启动本地前端后，运行相关截图和 QA；在上述桌面/移动尺寸实际检查布局、裁切、重叠、可读性和交互。
6. 根据渲染结果继续修正，直到满足成功标准。若后端或密钥不可用，明确区分环境问题与前端问题，并完成仍可执行的验证。

交付格式
- 先给一句结果摘要。
- 列出主要改动及其用户价值。
- 列出实际运行的验证命令和结果。
- 列出仍存在的限制或未验证项；没有则写“无已知遗留问题”。
- 不粘贴大段完整源码，只引用关键文件。

停止条件
- 需求范围内的改动已完成。
- 构建通过，相关页面在目标尺寸完成渲染检查，核心交互没有明显回退。
- 若同一环境阻塞在合理尝试后仍存在，停止盲目重试，说明具体阻塞、已完成部分和下一步最小操作。
```

## 2. Prompt：只做前端审计，不修改代码

```text
请对 `frontend/` 做一次证据驱动的前端优化审计，只读检查，不修改任何文件。

重点检查：
- 信息架构与运维工作流效率
- 视觉层级、间距、排版、颜色与设计令牌一致性
- 1440×900、1024×768、768×1024、390×844 响应式表现
- 加载、空数据、错误、离线、无权限和禁用状态
- 键盘操作、焦点、语义标签、对比度和非颜色状态提示
- Vue 响应式性能、轮询/SSE、ECharts/地图实例和事件清理
- 重复 CSS、魔法数字、`any`、组件职责和 API 类型安全

先阅读全局样式、主布局、路由、所有 views、API 封装和 QA 脚本。可运行构建和只读检查；如能启动项目，使用实际截图验证，不要只根据源码猜测。

输出按严重度排序的问题清单。每项必须包含：
1. 严重度 P0/P1/P2/P3
2. 文件与准确位置
3. 可复现的用户影响或技术风险
4. 具体修复建议
5. 验收方法

最后给出一个不超过 3 个阶段的实施顺序，并区分“快速收益”和“结构性改进”。没有证据的问题不要列出。
```

## 4. Prompt：移动端与响应式专项

```text
请直接修复 `frontend/` 的移动端和响应式体验，重点检查 390×844、768×1024、1024×768，同时确保 1440×900 不回退。

重点范围：主导航、页头、Dashboard、Monitor、Control、Alarms、DeviceManage、Chat、Users。

验收标准：
- 无页面级横向滚动、重叠、裁切或被固定区域遮挡的内容。
- 导航在窄屏仍有清晰入口、当前页反馈、可访问名称和足够点击区域。
- 表格在小屏采用合理的列优先级、滚动区域或详情展开，不简单隐藏关键字段。
- 地图、ECharts、筛选器、对话框和表单在旋转或尺寸变化后正确重排/resize。
- 主操作在单手场景可达，按钮和输入框不过密；中文长文本和大数值不会撑破布局。
- 焦点顺序与视觉顺序一致，软键盘出现时登录和聊天输入仍可使用。

先用实际浏览器截图定位问题，再实施修复。优先用 Grid/Flex、minmax、clamp、容器约束和清晰断点解决根因，避免按设备堆叠大量特例。完成后运行构建与多尺寸截图，并报告每个尺寸的结果。
```

## 5. Prompt：性能与稳定性专项

```text
请对 `frontend/` 进行性能与运行稳定性优化并直接实施，视觉和功能不得回退。

重点检查：
- 路由首屏体积、重型模块是否按需加载
- Element Plus 与图标的导入方式
- ECharts 和高德地图的创建、更新、resize、销毁
- 5 秒轮询、SSE、并发请求、竞态、重复刷新和卸载后的状态更新
- 深度 watch、computed、列表 key、大数据表格和重复 DOM 更新
- 图片尺寸、字体加载、布局偏移和长任务
- Axios 错误处理、请求取消、重复提交和慢网恢复

约束：
- 先用构建产物、浏览器性能数据或代码路径给出基线；不要凭感觉微优化。
- 不改变 API 契约，不删除真实功能，不以降低数据刷新正确性换取分数。
- 不随意增加依赖；每项优化需有可说明的收益。
- 对异步任务建立清晰的取消、去重或最新请求获胜策略。

完成后运行 `npm run build` 和相关页面 smoke test，汇报优化前后可获取的指标、改动文件、风险与验证结果。无法测量的收益不要伪造数字。
```

## 6. Prompt：可访问性专项

```text
请直接把 `frontend/` 的核心流程优化到 WCAG 2.2 AA 的合理目标，优先处理 Login、主导航、Dashboard、Control、Alarms、Chat。

检查并修复：
- HTML 语义、标题层级、landmark、表单 label 和错误关联
- 键盘访问、焦点顺序、focus-visible、对话框焦点管理和 Escape 行为
- 文字/背景对比度、非文字控件对比度、状态只靠颜色表达的问题
- 图标按钮的 accessible name、图表/地图的替代摘要
- 动态刷新、告警、表单错误和成功消息的适当 live region
- 触控目标、缩放、中文长文本、减少动态效果偏好

保留当前视觉方向，优先修复真实障碍，不机械添加 ARIA；原生语义足够时不要重复 ARIA。完成后运行构建、键盘走查和可执行的自动检查，并说明自动测试无法覆盖的人工检查项。
```

## 7. Prompt：仪表盘、图表与地图专项

```text
请直接优化 `frontend/src/views/Dashboard.vue` 以及它依赖的图表和地图工具，使其更适合智慧路灯运维人员快速判断全网状态。

目标：
- 5 秒内回答：设备总量、在线/离线情况、关键异常、当前照度趋势、异常设备位置。
- 保留 ECharts、高德地图、现有 API 与刷新逻辑。
- 指标、图表、地图、筛选和设备列表形成明确的阅读顺序，不相互争抢注意力。

要求：
- 指标必须含清晰标签、单位、数据时间或刷新状态；大数值和零值稳定显示。
- 图表轴、单位、tooltip、图例和时间范围清晰，空数据与错误状态完整；不要用面积和装饰夸大变化。
- 地图点位在线/离线不只靠颜色区分；加载失败、缺少密钥和重试行为清晰。
- 筛选器和地图工具使用熟悉图标、可访问名称、选中态和键盘焦点。
- 修复重复刷新、旧请求覆盖新请求、图表/地图未销毁或 resize 不正确的问题。
- 在 1440×900、1024×768、390×844 实际渲染检查，不允许地图遮挡控件、图表被压扁或设备表关键字段不可见。

完成后运行构建、截图与相关 QA；基于渲染结果继续修正。交付时说明信息层级变化、数据行为变化（若有）和验证结果。
```

## 8. Prompt：最终视觉 QA 与回归修复

```text
请对当前前端改动执行最终视觉 QA 和回归修复。不要新增功能，只修复发现的问题。

执行：
1. 运行 `npm run build`。
2. 启动前端，并检查 /login、/dashboard、/monitor、/control、/alarms、/devices、/chat、/users。
3. 至少在 1440×900、1024×768、768×1024、390×844 截图。
4. 检查空白页、控制台错误、失败请求的前端表现、横向溢出、重叠、裁切、字体回退、低对比度、错误 z-index、布局跳动和不可点击控件。
5. 用键盘走查登录、导航、筛选、表单提交、告警确认和聊天输入。
6. 检查轮询、SSE、图表和地图在切换路由后没有重复实例或泄漏。

发现问题后直接修复并重复验证，直到构建通过且没有 P0/P1 问题。不要删除测试或隐藏失败。若 QA 脚本中的断言已经过时，先证明它与当前明确设计契约不一致，再做最小更新。

最终只输出：
- 修复的问题
- 验证命令与结果
- 各视口检查结论
- 仍未解决的问题及原因
```

## 9. 快速补充指令

可将以下内容追加到任一 Prompt 末尾：

```text
请保持改动最小：不新增依赖，不重写无关文件，不改变 API，只修复本次目标。
```

```text
有参考截图时，将截图视为视觉与布局证据；保留项目真实数据和交互，不把截图中的假数据硬编码进实现。
```

```text
如果你只能给出计划而不能编辑文件，请明确说明能力限制；不要把计划伪装成已完成的实现。
```

```text
先完成一个页面并渲染验收，再把已验证的设计模式推广到其他页面，避免一次性全站重写。
```
