## 1. 通用约定

| 项 | 值 | 说明 |
|---|---|---|
| Base URL | `/api` | 开发环境经 Vite 代理到 `http://localhost:8080`（见 `vite.config.ts`） |
| 鉴权头 | `Authorization: Bearer <token>` | token 来自登录接口，前端存 `localStorage['token']`，由 `request.ts` 拦截器统一注入 |
| 数据格式 | JSON, UTF-8 | axios 自动序列化 |
| 超时 | 10000ms | `request.ts` |

### 1.1 统一响应体

所有接口返回 `{ code, message, data }`：

```json
{ "code": 0, "message": "ok", "data": { } }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `0` = 成功；非 0 = 业务错误 |
| `message` | string | 成功为 `"ok"`，失败为中文描述 |
| `data` | T | 业务数据；失败时为 `null` |

**⚠️ HTTP 状态码恒为 200。** 业务失败只体现在 `body.code`，前端判断 `code !== 0` 即失败（见 `request.ts`）。

### 1.2 时间戳约定

所有 `ts` / `start` / `end` / `lastSeen` / `createdAt` 均为**毫秒级 Unix 时间戳**（`Long`）。

### 1.3 前端降级机制（约定接口专用）

- `request.ts` 支持 `silent` 请求配置：请求失败时不弹全局错误提示，由调用方降级处理。
- `src/api/helper.ts` 的 `probe(promise, fallback)`：成功返回 `{ ready: true, data }`，失败返回 `{ ready: false, data: fallback }`。
- 页面收到 `ready: false` 时展示 `NotReadyBanner`（后端服务未就绪）并禁用相关操作；轮询类页面每次请求重新探针，**后端接口就绪后自动恢复**。

### 1.4 前端 TypeScript 类型来源

所有 `data` 结构的 TS 类型定义在 `src/api/*.ts`，本文档与之一一对应，后端响应 JSON 需与之完全吻合。

## 3. 已实现接口（✅）

### 3.1 用户登录

`POST /api/auth/login`

调用：`Login.vue` → `login(username, password)`（`src/api/auth.ts`）

**请求体**

```json
{ "username": "admin", "password": "123456" }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 用户名 |
| `password` | string | 是 | 密码 |

**成功响应 `data`**

```json
{ "token": "mock-jwt-token", "username": "admin", "role": "municipal" }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `token` | string | 当前恒为 `"mock-jwt-token"`，后端不校验 |
| `username` | string | 登录用户名 |
| `role` | string | 角色，当前恒为 `"municipal"` |

**失败**：`code=401`，`message="用户名或密码错误"`。前端登录页已内置 `admin` / `123456` 演示账号。

### 3.2 大屏总览统计

`GET /api/dashboard/overview`

调用：`Dashboard.vue` → `getOverview()`（`src/api/device.ts`）

**请求参数**：无

**成功响应 `data`**

```json
{ "totalDevices": 12, "onlineCount": 10, "offlineCount": 0, "avgLux": 235.67 }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `totalDevices` | long | 设备总数 |
| `onlineCount` | long | 在线设备数（`status == "ONLINE"`） |
| `offlineCount` | long | 离线设备数 |

### 3.3 设备列表

`GET /api/devices/{deviceId}/light`

**路径参数**

| 参数 | 类型 | 说明 |

### 3.5 查询光照历史

`GET /api/light/history`

调用：`Dashboard.vue`（大屏趋势）/ `Monitor.vue`（趋势）→ `getHistory(deviceId, start, end)`（`src/api/device.ts`）

**Query 参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `deviceId` | string | 是 | 设备编号 |
| `start` | long | 是 | 起始毫秒时间戳（闭区间） |
| `end` | long | 是 | 结束毫秒时间戳（闭区间） |

**前端实际传参**：
- Dashboard：`end = Date.now()`，`start = end - 时间段`，时间段可切换 `24h / 7d / 30d`
- Monitor：`end = Date.now()`，`start = end - 时间段`，时间段可切换 `24h / 7d`

**成功响应 `data`**（按 `ts` 升序）

```json
{
  "deviceId": "SL-001",
  "points": [
    { "ts": 1755748800000, "lux": 12.3 },
    { "ts": 1755752400000, "lux": 45.8 }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `deviceId` | string | 设备编号 |
| `points` | array | 时间序列，元素 `{ ts: long, lux: double }` |

> ⚠️ 三个参数**均必填**；无数据时返回 `points: []`；参数缺失会返回 Spring 默认错误页而非 `ApiResponse`，前端按「请求失败」容错。

## 6. 建议的后端实现约束

1. **判 `code` 不判 HTTP 状态**：所有接口业务结果统一 `{ code, message, data }`，HTTP 恒 200。
2. **错误码语义**：沿用 `0` 成功 / `400` 参数或资源错误（如设备不存在）/ `401` 登录失败 / 其他业务码自定义。
3. **设备标识统一用 `code`**：`deviceId` 路径/查询参数均为设备编号。
4. **约定接口请按上述请求/响应结构实现**，前端 `src/api/*.ts` 已按此封装，实现后无需改动前端即可联调。
5. **参数缺失/服务异常**：建议补充全局异常处理器统一返回 `ApiResponse`，避免前端收到 Spring 默认错误页。
