## 1. 通用约定

| 项 | 值 | 说明 |
|---|---|---|
| Base URL | `/api` | 开发环境经 Vite 代理到 `http://localhost:8080`（见 `vite.config.ts`） |
| 鉴权头 | `Authorization: Bearer <token>` | token 为登录接口返回的真实 JWT，前端存 `localStorage['token']`，由 `request.ts` 拦截器统一注入 |
| 数据格式 | JSON, UTF-8 | axios 自动序列化 |
| 超时 | 10000ms | `request.ts` |

### 1.1 统一响应体

所有接口返回 `{ code, message, data }`：

```json
{ "code": 0, "message": "ok", "data": { } }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `0` = 成功；非 0 = 业务错误 |
| `message` | string | 成功为 `"ok"`，失败为中文描述 |
| `data` | T | 业务数据；失败时为 `null` |

**⚠️ HTTP 状态码恒为 200。** 业务失败只体现在 `body.code`，前端判断 `code !== 0` 即失败（见 `request.ts`）。

### 1.2 鉴权说明（真实 JWT，全站强制）

- 后端已启用 Spring Security（`backend/.../config/SecurityConfig.java`）：**除 `POST /api/auth/login` 与 `/events`（SSE/WebSocket）外，其余所有接口均要求认证**。
- 未登录 / 携带无效 token 访问受保护接口 → **HTTP 200 + `body.code=401`**，`message="未登录或 token 无效"`。
- 权限不足 → **HTTP 200 + `body.code=403`**，`message="权限不足"`（当前后端仅区分"已认证/未认证"，未启用角色级细分，403 为框架预留）。
- token 由 `POST /api/auth/login` 签发：`AuthService` 查 `sys_user` 表、`PasswordEncoder`（BCrypt）验密，`JwtUtil.generateToken` 生成**真实 JWT**（不再返回 mock token）。
- 前端流程：`Login.vue` 登录成功后将 `data.token` 写入 `localStorage['token']`；`request.ts` 拦截器为每个请求自动附加 `Authorization: Bearer <token>`。前端以 `code === 401` 作为未登录信号。

### 1.3 错误码表

| code | 含义 | 常见 message |
|---|---|---|
| `0` | 成功 | `ok` |
| `400` | 参数或资源错误 | `设备不存在`、`设备编号已存在`、`请输入有效经纬度：经度 -180 至 180，纬度 -90 至 90`、`阈值必须在 0-500 之间`、`告警不存在`、`用户名已存在`、`角色必须为 admin / municipal / operator`、`缺少必要参数: <name>`、`参数类型错误: <name>`、`question 不能为空` |
| `401` | 未认证 | `用户名或密码错误`（登录失败）、`未登录或 token 无效`（安全过滤器） |
| `403` | 权限不足 | `权限不足` |
| `500` | 服务器内部错误 | `服务器内部错误: <异常信息>` |

### 1.4 时间戳约定

所有 `ts` / `start` / `end` / `lastSeen` / `createdAt` 均为**毫秒级 Unix 时间戳**（`Long`）。

### 1.5 全局异常处理（已启用）

后端已有 `exception/GlobalExceptionHandler.java`（`@RestControllerAdvice`），所有异常统一返回 `ApiResponse`，**前端无需处理 Spring 默认错误页**：

- 缺少必要参数（如 `/light/history` 缺 `start`）→ `code=400` `缺少必要参数: <name>`
- 参数类型错误（如 `start` 传字符串）→ `code=400` `参数类型错误: <name>`
- 业务参数错误（`BadRequestException`，如空问题）→ `code=400`
- 其余未捕获异常 → `code=500` `服务器内部错误: <msg>`

### 1.6 前端降级机制

- `request.ts` 支持 `silent` 请求配置：请求失败时不弹全局错误提示，由调用方降级处理。
- `src/api/helper.ts` 的 `probe(promise, fallback)`：成功 → `{ ready: true, data }`；失败 → `{ ready: false, data: fallback }`。
- 页面收到 `ready: false` 时展示 `NotReadyBanner`（后端服务未就绪）并禁用相关操作；轮询类（告警、顶栏通知）每次请求重新探针，**后端就绪后自动恢复**。

### 1.7 前端 TypeScript 类型来源

所有 `data` 结构的 TS 类型定义在 `src/api/*.ts`，本文档与之一一对应，后端响应 JSON 需与之完全吻合。

## 3. 接口详情

### 3.1 用户登录

`POST /api/auth/login`

调用：`Login.vue` → `login(username, password)`（`src/api/auth.ts`）

**请求体**

```json
{ "username": "admin", "password": "123456" }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 用户名 |
| `password` | string | 是 | 密码 |

**成功响应 `data`**

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJhZG1pbiIsInJvbGUiOiJhZG1pbiIs...",
  "username": "admin",
  "role": "admin"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `token` | string | **真实 JWT**，后续请求需携带 `Authorization: Bearer <token>` |
| `username` | string | 登录用户名 |
| `role` | string | `admin` / `municipal` / `operator`（取自数据库 `sys_user.role`） |

**失败**：账号或密码错误 → `code=401`，`message="用户名或密码错误"`。

> ⚠️ 后端真实查库校验（`sys_user` 表 + BCrypt），不再是 mock token。前端登录页内置 `admin` / `123456` 演示账号（需数据库中已初始化该用户）。

### 3.5 查询光照历史

`GET /api/light/history`

调用：`Dashboard.vue`（大屏趋势）/ `Monitor.vue`（趋势）→ `getHistory(deviceId, start, end)`（`src/api/device.ts`）

**Query 参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `deviceId` | string | 是 | 设备编号 |
| `start` | long | 是 | 起始毫秒时间戳（闭区间） |
| `end` | long | 是 | 结束毫秒时间戳（闭区间） |

**前端实际传参**：
- Dashboard 区间模式：`end = Date.now()`，`start = end - 时间段`，时间段可切换 `24h / 7d / 30d`
- Dashboard **单日模式**（点选日期条"今天 / MM-DD"）：`start = 所选日期 00:00`，`end = start + 86400000`（当天全天）
- Monitor：`end = Date.now()`，`start = end - 时间段`，时间段可切换 `24h / 7d`

**成功响应 `data`**（按 `ts` 升序）

```json
{
  "deviceId": "SL-001",
  "points": [
    { "ts": 1755748800000, "lux": 12.3 },
    { "ts": 1755752400000, "lux": 45.8 }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `deviceId` | string | 设备编号 |
| `points` | array | 时间序列，元素 `{ ts: long, lux: double }` |

> ⚠️ 三个参数**均必填**；缺参返回 `code=400 缺少必要参数`（全局异常处理器兜底）；无数据时返回 `points: []`。

### 3.6 AI 运维问答（真实 Agent）

调用：`Chat.vue` → `ask(question)`（`src/api/agent.ts`）

**请求体**


|---|---|---|---|

**成功响应 `data`**

```json

  "answer": "根据系统实时数据，设备 SL-001 当前为 ONLINE 状态，最近一次照度 320.5 Lux。",
  "sources": [
    { "title": "系统设备数据", "section": "system_data", "score": 1.0 },
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 用户名，唯一 |

## 5. 联调注意事项

1. **先登录拿 token**：除 `/api/auth/login` 外所有接口都要求 `Authorization: Bearer <token>`，未带 token 会收到 `code=401`。前端 `request.ts` 已自动注入，联调 Postman/curl 时需手动携带。
2. **判 `code` 不判 HTTP 状态**：所有接口业务结果统一 `{ code, message, data }`，HTTP 恒 200。
3. **设备标识统一用 `code`**：`deviceId` 路径/查询参数均为设备编号（如 `SL-001`），非数据库主键 `id`。
4. **添加设备必须带经纬度**：`longitude` / `latitude` 为必填且范围受限（经度 ±180、纬度 ±90）。
5. **智能体 `sources[].section`** 为来源类型 `knowledge` / `system_data`，前端展示时可按此区分知识库引用与系统实时数据。
6. **降级机制仍有效**：告警、通知等请求带 `silent`，后端未就绪时前端展示「服务未就绪」并自动恢复，不影响其他模块。
